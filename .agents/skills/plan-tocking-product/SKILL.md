# Tocking 제품 기획

## Overview

Tocking의 기능을 구현 가능한 작은 제품 단위로 정의한다. UI 설계나 코드 구현은
하지 않고, 무엇을 왜 만들어야 하는지와 최소 동작 범위를 정한다.

## Workflow

1. `AGENTS.md`를 읽고 제품 목적과 현재 하네스 메모를 확인한다.
2. 요청이 큰 기획인지 작은 기획인지 먼저 분류한다.
3. 큰 기획은 제품 목표, 사용자 문제, 포함 범위, 제외 범위, 관련 작은 기획으로
   나눈다.
4. 작은 기획은 하나의 Skill이 처리할 수 있는 단일 기능 또는 사용자 문제로
   좁힌다.
5. 목표 사용자, 핵심 상황, 입력 데이터, 기대 결과를 정의한다.
6. Naver 추천 주제와 OpenAI API가 필요한지 여부를 분리해 적는다.
7. UI, API, 도메인, QA로 넘길 수 있는 최소 산출물을 만든다.
8. 새 결정이나 제약은 `AGENTS.md`와 필요한 경우 `docs/state.md`에 갱신한다.

## Output

- 기능 목표
- 큰 기획 또는 작은 기획 여부
- 소속 큰 기획
- 사용자 흐름 요약
- 필요한 데이터와 API
- 최소 성공 조건
- 다음에 사용할 권장 스킬
